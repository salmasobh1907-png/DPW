What IT needs to give, task by task

The pricing tool today is a demo page with dummy data. To run it for real, each task needs a few building blocks that only IT can provide. This page lists those blocks once, then maps every task to them and shows how each task would work end to end.

الصفحة دي بتقول: كل حاجة في الأداة محتاجة إيه من IT، وهتشتغل إزاي من الأول للآخر.

Contact Salma Ismail, Ocean Freight PricingStatus proposal, nothing built in DP World systems yet
The short version for IT 1. Put the page behind DP World login, with roles from Entra ID groups. 2. Give the app a safe place to store team data. 3. Let the app read the pricing shared mailboxes and the Rate Bank, read-only and limited to named items. 4. Run the jobs on a company account, not on any one person's computer. 5. Decide with HR and Legal whether "My shift" time tracking is allowed.

Task 1 · in the demo

Shared inbox cases: SLA, routing, reassign, Team KPIs, My shift

Every email that reaches a pricing mailbox becomes a case with an owner and an SLA clock. The clock runs in working hours (Sun to Thu, Cairo) until the first reply goes out. Managers see Team KPIs, and each person sees their own shift.

Task 2

Rate Bank reading (export and import rates)

The tool reads the team's Rate Bank Export and Import files, finds the lowest standard 40' per lane and shows validity. It only reads. It never writes to them.

الأداة بتقرا ملفات الـ Rate Bank بس، عمرها ما بتكتب فيها.

The Rate Bank owner updates itExcel on SharePoint, as today
A scheduled job reads itevery hour, on a company service account (A1)
Read-only permission on those 2 filesGraph Sites.Selected, read only (D2)
Rates are cleanedstandard rows only; no validity = end of month
Pricing sees fresh rateswith "last read" time on screen
Today

The prototype uses a dummy Rate Bank. No real file is connected.

Rule that must stay

View only. Sheets with passwords are never opened. Later the same job can read NPM instead of Excel.

Task 3

Pricing Hub and Sales pages (roles)

Pricing sees buy rates, profit and sell. Sales see only the sell rate and quote. Today this is a switch button in the page, which is not real protection.

الـ sales لازم ما يشوفوش الـ buy rate. ده محتاج IT يعمل roles حقيقية، مش زرار.

Person opens the toolDP World login (ID1)
Entra ID says which groupPricing, Sales, Leads (ID2)
Server sends only allowed datasales never receive buy rates in the browser
Page shows the right screensPricing Hub or Sales pages
Why the server part mattersIf buy rates are inside the page and only hidden, a sales user can still find them. For real roles, the buy rates must stay on the server (H1 + D1) and only pricing users receive them.
Task 4

Quotation email (buy + profit = sell)

Pricing picks a rate, the tool adds profit on ocean freight only (fixed 25/50 only for China dry export ports, otherwise set from the market gap), and writes the quote email.

الأداة بتكتب الإيميل كـ draft، وإنتي اللي بتدوسي Send بنفسك.

Choose lane and ratebuy rate from Rate Bank
Tool adds profitshows buy, profit and sell
Draft is created in Outlookdraft only, never auto-send (M3)
Person checks and presses Sendfrom pricing@ or own box
Quote saved to the logReference Sheet replacement (D1)
Task 5

Quotes log, feedback and declines (Reference Sheet)

Every request and quote is logged with sales PIC, pricing PIC, lane, date and result (won, lost, no feedback). Same thread and subject in the same month counts as one request.

بدل ما نكتب في الـ Reference Sheet بإيدينا، كل quote تتسجل لوحدها في قاعدة بيانات.

Case or quote is savedautomatically, with the person's name
Stored in a team listSharePoint List or Dataverse with audit log (D1)
Sales add feedbackwon, lost, price too high
Monthly report reads itno copy-paste into Excel
The current Reference Sheet stays view only. The new log starts fresh, or IT imports a copy once.

Task 7

Sokhna terminal rule

Sokhna has two terminals. Every Sokhna rate must show its terminal, DP World terminal rates come first, and the tool warns before a sales quote uses another terminal's rate.

ده rule جوه الأداة، مش محتاج حاجة كبيرة من IT. المهم إن اسم الـ terminal يبقى موجود في الداتا.

Rate row has a "Terminal" valuenew column in Rate Bank, or a field from NPM

No new IT block. Only a data question: can the Rate Bank owner add a Terminal column, and does NPM store the terminal on each contract?
